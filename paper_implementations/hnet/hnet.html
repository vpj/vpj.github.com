#

The Hierarchical Model

This file puts the parts of Dynamic Chunking for End-to-End Hierarchical Sequence Modeling together into one model.

An H-Net with $S$ stages has an encoder $\mathcal{E}^s$ and a decoder $\mathcal{D}^s$ for each stage $s = 0, \dots, S - 1$, and one main network $\mathcal{M}$ at the center. The input of stage 0 is the sequence of byte embeddings $x^0$. Each stage does these steps (Eqs. 1-3 in the paper):

\begin{align*} \hat{x}^s &= \mathcal{E}^s(x^s) \\ (x^{s+1}, p^s) &= \operatorname{Chunk}(\hat{x}^s) \\ \hat{z}^{s+1} &= \text{the next stage, on } x^{s+1} \\ z^s &= \operatorname{Dechunk}(\hat{z}^{s+1}, p^s) + \operatorname{Linear}(\hat{x}^s) \\ \hat{z}^s &= \mathcal{D}^s(z^s) \end{align*}

The next stage of the last outer stage is the main network: $\hat{z}^S = \mathcal{M}(x^S)$. $\operatorname{Chunk}$ and $\operatorname{Dechunk}$ are the layers in dynamic chunking, and $p^s$ are the boundary probabilities of stage $s$. Thus the main network of a 1-stage H-Net is itself replaced by a 1-stage H-Net to give 2 stages.

The sequence gets shorter at each stage, so the inner networks can be wider for the same computation. The paper uses widths with $D^0 \le D^1 \le \dots \le D^S$, and puts most of the parameters in the main network.

Configuration

  • d_model: the widths $D^0, \dots, D^S$, one for each stage and one for the main network.
  • target_ratio: the target ratios $N^0, \dots, N^{S-1}$ of the ratio loss, one for each stage. Its length sets the number of stages $S$.
  • outer_layers and main_layers: the number of blocks in each encoder and decoder, and in the main network.
  • alpha: $\alpha$, the weight of the ratio loss. The paper uses $\alpha = 0.03$ in all experiments.
Paper: four layers in each encoder and decoder

The paper always uses four Mamba-2 layers in each encoder and decoder. The toy experiment uses two Transformer blocks; layers says why there is no Mamba-2.

One stage

An HNet is one stage $s$. Its main network is either the next stage, another HNet, or, at $s = S$, the main network $\mathcal{M}$ itself.

30        self.d_model = config.d_model[stage]

34            return

The encoder $\mathcal{E}^s$, the routing module and the chunk layer of this stage.

37        self.routing = RoutingModule(self.d_model)
38        self.chunk = ChunkLayer()

The next stage is wider, $D^{s+1} \ge D^s$. To make a chunk vector wider, the model appends a learned vector of $D^{s+1} - D^s$ dimensions, the same for each chunk. On the way back, it keeps the first $D^s$ dimensions. This needs no extra linear layer. The paper takes the method from SpaceByte.

39        self.extra_dims = nn.Parameter(torch.zeros(config.d_model[stage + 1] - self.d_model))
#

The next stage. This is the recursion.

40        self.main = HNet(config, stage + 1)
# 
41        self.dechunk = DechunkLayer()

The residual projection $\operatorname{Linear}(\hat{x}^s)$ starts at zero. Then, at the start of training, the decoder gets only the output of the next stage, and the model must use the main network. The residual grows when the decoder needs the detail of each byte.

Residual starts at exactly zero

The paper says the residual starts "close to 0". The authors' code sets it to exactly zero, and so do we.

Forward

x is $x^s$, shape [batch, L, d_model], and mask marks the positions with data. The method returns $\hat{z}^s$ and the routing output of this stage and every inner stage, for the ratio losses.

47    def forward(self, x: torch.Tensor, mask: torch.Tensor) -> tuple[torch.Tensor, list[Routing]]:
#

$\hat{z}^S = \mathcal{M}(x^S)$. The main network makes no chunks.

48        if self.is_main:
49            return self.main(x), []
#

$\hat{x}^s = \mathcal{E}^s(x^s)$

51        x_hat = self.encoder(x)
#

The boundary probabilities $p^s$ and the boundaries.

52        routing = self.routing(x_hat, mask)
#

$x^{s+1}$: the chunks, with their mask.

53        x_next, mask_next, order = self.chunk(x_hat, routing.b)
#

Widen the chunks from $D^s$ to $D^{s+1}$.

54        x_next = torch.cat([x_next, self.extra_dims.expand(*x_next.shape[:-1], -1)], dim=-1)
#

$\hat{z}^{s+1}$ from the next stage.

55        z_hat_next, inner_routings = self.main(x_next, mask_next)
# $$z^s = \operatorname{Dechunk}(\hat{z}^{s+1}, p^s) + \operatorname{Linear}(\hat{x}^s)$$

after the model keeps the first $D^s$ dimensions of $\hat{z}^{s+1}$.

56        z = self.dechunk(z_hat_next[..., : self.d_model], routing, order) + self.residual(x_hat)
#

$\hat{z}^s = \mathcal{D}^s(z^s)$

57        return self.decoder(z), [routing] + inner_routings

Learning rate for each stage

The stages see sequences of very different lengths and have different widths. One learning rate for all of them trains them badly. The paper multiplies the base learning rate by a factor $\lambda^s$ for each stage, from two scaling rules:

  • the learning rate grows with the square root of the batch size, here the number of positions that the stage sees;
  • the learning rate falls with the square root of the width.

The base learning rate is for a tokenized Transformer of width $D^S$, with $N_{\text{GPT}}$ bytes for each token. For $L^0$ bytes it sees $L^0 / N_{\text{GPT}}$ positions. Stage $s$ sees $L^0 / \prod_{i \lt s} N^i$ positions. The two rules give (Eq. 11 in the paper):

\begin{align*} \lambda^s &= \sqrt{\frac{N_{\text{GPT}}}{\prod_{i \lt s} N^i} \cdot \frac{D^S}{D^s}} \\ &= \sqrt{N_{\text{GPT}} \frac{\prod_{i=s}^{S} N^i}{\prod_{i=0}^{S} N^i} \cdot \frac{D^S}{D^s}} \end{align*}

with $N^S = 1$. The second line is the form of the paper.

The paper does not define $N_{\text{GPT}}$. We set it to $\prod_{i \lt S} N^i$, the target number of bytes for each position of the main network. Then the main network has $\lambda^S = 1$: it uses the base learning rate. In the toy experiment ($N^0 = 4$, $D^0 = 128$, $D^1 = 192$) this gives the outer stage

$$\lambda^0 = \sqrt{4 \cdot 192 / 128} = 2.45$$

The paper reports that values such as $2.0$, $1.5$ and $1.0$ for three stages work well in general. The paper also finds that the larger learning rate of the outer stages makes the boundaries learn faster.

60def lr_multipliers(config: HNetConfig, n_gpt: float) -> list[float]:
61    n = list(config.target_ratio) + [1.0]
62    d = config.d_model
63    return [math.sqrt(n_gpt * math.prod(n[s:]) / math.prod(n) * d[-1] / d[s]) for s in range(len(d))]

Byte-level language model

The H-Net reads bytes, so the vocabulary has 256 entries. The embedding table and the output head are small: $2 \times 256 \times D^0$ parameters. A tokenized model with a vocabulary of 50,000 tokens needs about 200 times as many.

74class HNetLM(nn.Module):
# 
75    def __init__(self, config: HNetConfig):
76        super().__init__()
77        self.config = config
78        self.embedding = nn.Embedding(256, config.d_model[0])
79        self.hnet = HNet(config)
80        self.head = nn.Linear(config.d_model[0], 256, bias=False)
81        self.ratio_losses = nn.ModuleList([RatioLoss(n) for n in config.target_ratio])
#

The logits of the next byte at each position, and the routing outputs of all stages.

83    def forward(self, tokens: torch.Tensor, mask: torch.Tensor) -> tuple[torch.Tensor, list[Routing]]:
84        y, routings = self.hnet(self.embedding(tokens), mask)
85        return self.head(y), routings

Training loss

The next-byte loss plus the ratio loss of each stage (Section 2.2.3 in the paper):

$$\mathcal{L} = \mathcal{L}_{\text{AR}} + \alpha \sum_{s=0}^{S-1} \mathcal{L}_{\text{ratio}}^s$$

where $\mathcal{L}_{\text{AR}}$ is the mean cross-entropy of the next byte, in nats.

87    def loss(self, tokens: torch.Tensor, mask: torch.Tensor) -> LMLoss:
#

The model reads bytes $1, \dots, L - 1$ and predicts bytes $2, \dots, L$.

88        logits, routings = self(tokens[:, :-1], mask[:, :-1])
# $$\mathcal{L}_{\text{AR}} = -\frac{1}{T} \sum_{t} \log \pi_t(y_{t+1})$$

where $y_t$ is byte $t$, $\pi_t$ is the softmax of the logits at position $t$, and the sum is over the $T$ targets that are not padding.

89        targets = mask[:, 1:]
90        autoregressive = F.cross_entropy(logits[targets], tokens[:, 1:][targets])
#

$\mathcal{L}_{\text{ratio}}^s$ for each stage, with its own target $N^s$.

91        ratio = [loss(routing) for loss, routing in zip(self.ratio_losses, routings)]
# $$\mathcal{L} = \mathcal{L}_{\text{AR}} + \alpha \sum_s \mathcal{L}_{\text{ratio}}^s$$ 
92        total = autoregressive + self.config.alpha * sum(ratio)
# 
93        return LMLoss(total=total, autoregressive=autoregressive, ratio=ratio, routings=routings)

Parameter groups

One optimizer group for each stage, with the learning rate $\lambda^s$ times the base rate. A stage object contains its inner stages, so the method starts at the main network and goes outward. Each stage gets only the parameters that an inner stage did not take. The byte embedding and the output head work on bytes, so they belong to stage 0.

95    def param_groups(self, lr: float, n_gpt: float) -> list[dict]:
96        multipliers = lr_multipliers(self.config, n_gpt)
97        groups = [[] for _ in multipliers]
98        inner_ids = set()
99        for stage in reversed(range(len(multipliers))):
100            module = self.stage_module(stage)
101            params = [param for param in module.parameters() if id(param) not in inner_ids]
102            groups[stage].extend(params)
103            inner_ids.update(id(param) for param in params)
104        groups[0].extend([*self.embedding.parameters(), *self.head.parameters()])
105        return [dict(params=params, lr=lr * m) for params, m in zip(groups, multipliers)]
#

The HNet object of stage $s$, found through the chain of main networks.
