Dynamic Chunking

This file implements dynamic chunking from Dynamic Chunking for End-to-End Hierarchical Sequence Modeling (Section 2.2 in the paper). Dynamic chunking cuts the output of the encoder into chunks, gives the chunks to the main network, and changes the result back to one vector for each position.

The input is the encoder output $\hat{x}_t$ for the positions $t = 1, \dots, L$. These steps happen, in this order:

  1. The routing module gives each position a boundary probability $p_t$. A position starts a chunk if $p_t \ge 0.5$.
  2. The chunk layer keeps only the vectors at the start of each chunk.
  3. The main network processes the chunks. It is not in this file.
  4. The dechunk layer smooths the chunk outputs with the probabilities, then repeats each one over the positions of its chunk.
  5. The ratio loss keeps the number of chunks near a target.

The selection of positions is discrete and has no gradient. Two parts give the routing module a gradient. The smoothing in the dechunk layer uses $p_t$ as a weight. The upsampler multiplies each output by a confidence that depends on $p_t$. The derivations below show what each gradient tells the routing module.

Routing module

A boundary is likely where the meaning of the data changes, for example between two words. Then the encoder outputs on the two sides of the boundary are not similar. The routing module measures this with the cosine similarity of two adjacent positions (Eq. 4 in the paper):

\begin{align*} q_t &= W_q \hat{x}_t, \qquad k_t = W_k \hat{x}_t \\ p_t &= \frac{1}{2} \left( 1 - \frac{q_t^\top k_{t-1}}{\lVert q_t \rVert \lVert k_{t-1} \rVert} \right) \\ b_t &= \mathbb{1}\{p_t \ge 0.5\} \end{align*}

The cosine is in $[-1, 1]$, so $p_t$ is in $[0, 1]$. If the two vectors point in the same direction, $p_t = 0$. If they are orthogonal, $p_t = 0.5$ and the position starts a chunk. The first position has no neighbour. It always starts a chunk, with $p_1 = 1$.

$W_q$ and $W_k$ are learned. Thus the model learns which kind of difference marks a boundary.

Chunk layer

The chunk layer keeps the vectors $\hat{x}_t$ where $b_t = 1$, in their order, and discards the others (the downsampler in the paper). The $j$-th chunk is the vector at the $j$-th boundary. The main network reads these $M = \sum_t b_t$ vectors. The paper also tried mean pooling and attention over each chunk. The simple selection worked as well.

Each example in a batch can have a different number of chunks. We put the chunks of each example at the start of its row and pad the rest. A mask marks the chunks that hold data. The padding is always at the end of a row. All the networks are causal, so a padded position never changes a position with data.

Authors' code: packed rows, not padding

The authors' code puts all examples in one long row without padding, and gives the start of each example to its kernels. Padding is simpler to read. It costs computation on positions with no data.

Straight-through estimator

The straight-through estimator (STE) has the value 1, and the gradient of $c$ (Eq. 7 in the paper):

$$\operatorname{STE}(c) = c + \operatorname{sg}(1 - c)$$

where $\operatorname{sg}$ stops the gradient. In the forward pass the two terms add to 1. In the backward pass the second term is a constant, so $\partial \operatorname{STE}(c) / \partial c = 1$. The upsampler uses it to multiply by the confidence without a change to the values.

43def ste(c: torch.Tensor) -> torch.Tensor:
44    return c + (1 - c).detach()
#

Dechunk layer

The main network gives one output $\hat{z}_j$ for each chunk $j = 1, \dots, M$. The dechunk layer changes these $M$ vectors back to $L$ vectors, in two steps: it smooths the chunk outputs, then it upsamples them.

Let $P_j$ be the boundary probability at the position where chunk $j$ starts. All $P_j$ are at least $0.5$, and $P_1 = 1$.

47class DechunkLayer(nn.Module):

48    def forward(self, z_hat: torch.Tensor, routing: Routing, order: torch.Tensor) -> torch.Tensor:
#

$P_j$ comes from the same positions that the chunk layer selected.

49        z_bar = self.smooth(z_hat, routing.p.gather(1, order))
# 
50        return self.upsample(z_bar, routing)

Smoothing

The smoothing module makes an exponential moving average of the chunk outputs (Eq. 5 in the paper):

$$\bar{z}_j = P_j \hat{z}_j + (1 - P_j) \bar{z}_{j-1}$$

If the routing module is sure of a boundary ($P_j = 1$), then $\bar{z}_j = \hat{z}_j$. If it is not sure ($P_j$ near $0.5$), the chunk gets part of the earlier chunks.

A weighted average of the earlier chunks

Put the recursion into itself:

\begin{align*} \bar{z}_j &= P_j \hat{z}_j + (1 - P_j) \bar{z}_{j-1} \\ &= P_j \hat{z}_j + (1 - P_j) P_{j-1} \hat{z}_{j-1} \\ &\quad + (1 - P_j)(1 - P_{j-1}) \bar{z}_{j-2} \\ &= \sum_{i=1}^{j} w_{j,i} \, \hat{z}_i \end{align*}

with the weights

$$w_{j,i} = P_i \prod_{k=i+1}^{j} (1 - P_k)$$

The sum of the weights telescopes. Each step moves part of the remaining weight to the newest chunk:

$$\sum_{i=1}^{j} w_{j,i} = 1 - \prod_{i=1}^{j} (1 - P_i) = 1$$

The product is zero because $P_1 = 1$. Thus $\bar{z}_j$ is a weighted average of the outputs of chunks $1, \dots, j$. It never uses a later chunk, so the smoothing is causal.

The gradient that trains the boundary

The derivative of the smoothed vector with respect to its probability is

$$\frac{\partial \bar{z}_j}{\partial P_j} = \hat{z}_j - \bar{z}_{j-1}$$

This is the difference between the two choices: start a new chunk with $\hat{z}_j$, or keep the average $\bar{z}_{j-1}$ of the earlier chunks. If the loss is lower with more of $\hat{z}_j$, gradient descent makes $P_j$ larger, and the boundary becomes more certain. If the loss is lower with more of the earlier chunks, $P_j$ becomes smaller. When it goes below $0.5$, the position stops being a boundary. Without the smoothing, the output would not depend on $P_j$, and this signal would not exist.

Authors' code: the smoothing as a Mamba-2 scan

The recursion is a linear scan $h_j = a_j h_{j-1} + u_j$, with $a_j = 1 - P_j$ and $u_j = P_j \hat{z}_j$. The authors' code runs it with the scan kernel of Mamba-2, with the step size

$$\Delta_j = \log \frac{1}{1 - P_j}$$

so that $e^{-\Delta_j} = 1 - P_j$. That needs $P_j \lt 1$, so the code clamps $P_j$ to $[10^{-4}, 1 - 10^{-4}]$. We use a loop over the chunks. It is slower, but it needs no clamp.

Upsampling

Each position $t$ gets the smoothed output of the chunk that it is in. That chunk is the last one that started at or before $t$:

$$j(t) = \sum_{k=1}^{t} b_k, \qquad \tilde{z}_t = \bar{z}_{j(t)}$$

The upsampler then multiplies $\tilde{z}_t$ by the confidence $c_t$ of the routing module in its decision at $t$ (Eqs. 6, 8 and 9 in the paper):

\begin{align*} c_t &= p_t^{b_t} (1 - p_t)^{1 - b_t} \\ u_t &= \operatorname{STE}(c_t) \, \tilde{z}_t \end{align*}

So $c_t = p_t$ at a boundary and $c_t = 1 - p_t$ elsewhere. The value of $\operatorname{STE}(c_t)$ is 1, so the output is $u_t = \tilde{z}_t$. Only the gradient changes.

The gradient of the confidence

Let $\ell$ be the loss. The STE has a gradient of 1, and $\partial c_t / \partial p_t$ is $+1$ at a boundary and $-1$ elsewhere. Thus

$$\frac{\partial \ell}{\partial p_t} = \pm \left\langle \frac{\partial \ell}{\partial u_t}, \tilde{z}_t \right\rangle$$

with $+$ at a boundary and $-$ elsewhere. The inner product is negative if a larger $u_t$ along $\tilde{z}_t$ makes the loss lower. Then gradient descent makes $c_t$ larger in both cases:

  • at a boundary, $p_t$ becomes larger;
  • at another position, $p_t$ becomes smaller.

So the routing module becomes more certain of a decision when the chunk output helps the prediction at that position. Each position $t$ gives this signal, not only the boundaries.

Ratio loss

The next-byte loss alone does not fix the number of chunks. The model could keep every position, and then the main network gets no shorter input. It could also keep almost none, and then the main network gets too little information. The ratio loss pulls the model to a target of $N$ positions for each chunk (Eq. 10 in the paper):

$$\mathcal{L}_{\text{ratio}} = \tfrac{N}{N - 1} \big( (N - 1) F G + (1 - F)(1 - G) \big)$$

where $F = \frac{1}{L} \sum_t b_t$ is the fraction of positions that start a chunk, and $G = \frac{1}{L} \sum_t p_t$ is the mean boundary probability. $F$ has no gradient, because $b_t$ is a threshold. $G$ has a gradient, and the loss acts through it. The form comes from the load-balance loss of mixture-of-experts models, with two "experts": boundary and no boundary.

A simpler form

Multiply out the bracket and subtract 1:

\begin{align*} &(N - 1)(\mathcal{L}_{\text{ratio}} - 1) \\ &= N(N - 1) F G + N (1 - F)(1 - G) \\ &\quad - (N - 1) \\ &= N^2 F G - N F - N G + 1 \\ &= (N F - 1)(N G - 1) \end{align*}

Thus

$$\mathcal{L}_{\text{ratio}} = 1 + \frac{(N F - 1)(N G - 1)}{N - 1}$$

The loss is 1 if $F = 1/N$ or $G = 1/N$. It is less than 1 when $F$ and $G$ are on different sides of $1/N$, and more than 1 when they are on the same side.

The minimum when F = G

If $F = G$, the product is $(N F - 1)^2 \ge 0$. The minimum is $\mathcal{L}_{\text{ratio}} = 1$, at $F = G = 1/N$: one chunk for each $N$ positions. This is the case that the paper describes. The paper also says that the loss can be less than 1 when $F \ne G$. The simpler form shows how far it can go.

The minimum over all values

At $F = 1$ and $G = 0$, the product is $-(N - 1)$, so $\mathcal{L}_{\text{ratio}} = 0$. That is the minimum, but the routing module cannot get there. $F = 1$ needs $p_t \ge 0.5$ at every position, so $G \ge 0.5$.

The minimum that the routing module can get

Each boundary has $p_t \in [0.5, 1]$, and each other position has $p_t \in [0, 0.5)$. Add over the positions and divide by $L$:

$$\frac{F}{2} \le G \lt \frac{1 + F}{2}$$

The loss is less than 1 on two sides: $F \gt 1/N$ with $G \lt 1/N$, and $F \lt 1/N$ with $G \gt 1/N$. On the first side, the band gives a loss of at least $1 - 1/(8(N - 1))$, which is 0.958 for $N = 4$, at $F = 3/(2N)$ and $G = F/2$. On the second side, the loss is smallest at the largest $G$, which is $(1 + F)/2$. If $N \ge 3$, the product is then smallest at $F = 0$, $G \to \frac{1}{2}$:

$$\mathcal{L}_{\text{ratio}} \to 1 - \frac{N/2 - 1}{N - 1} = \frac{N}{2(N - 1)}$$

For $N = 4$ this is $2/3$. At $F = 0$ there are no boundaries, except the first position. Each other $p_t$ is just below $0.5$. Thus, of all the values that the routing module can get, the ratio loss is smallest for a model that makes no chunks, not at the target.

Why training does not go to zero chunks

A test builds the case with no chunks from a routing output and gets a loss of 0.667. Training does not go there in practice. If $F \lt 1/N$, the gradient through $G$ makes each $p_t$ larger. When $p_t$ passes $0.5$, a new boundary makes $F$ larger. Our experiment ended at a compression of 2.87 positions for each chunk: below the target of 4, but far from zero chunks. The weight $\alpha = 0.03$ of the ratio loss is also small compared with the next-byte loss.
