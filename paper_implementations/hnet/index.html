H-Net: Dynamic Chunking for End-to-End Hierarchical Sequence Modeling

This is a PyTorch implementation of Dynamic Chunking for End-to-End Hierarchical Sequence Modeling (Hwang, Wang and Gu, 2025).

A usual language model does not read text. It reads tokens from a tokenizer, and the tokenizer is made before the model trains. The tokenizer does not learn with the model, and it fixes where each token starts. An H-Net reads raw bytes. A small encoder processes the bytes. Then the model itself decides where each chunk starts, and a large main network works on the chunks. A decoder changes the output back to one vector for each byte. The whole model trains end to end on next-byte prediction. Thus the chunks are a result of the training, not an input to it.

The new part is dynamic chunking. It is one mechanism, so all its parts are in one file:

  • Dynamic chunking - the routing module that predicts boundaries, the chunk layer, the dechunk layer that smooths and upsamples, and the ratio loss that sets the compression.
  • H-Net - the recursive model that puts the encoder, the chunking, the main network and the decoder together, and the byte-level language model with its loss.
  • Layers - the Transformer blocks that we use for every network.
  • Experiment - a 1-stage H-Net that trains on a CPU in a few minutes, and the chunks that it learns.

The paper uses Mamba-2 layers in the encoder and the decoder. Mamba-2 needs custom GPU kernels. This implementation uses Transformer blocks for all networks, so that it runs on a CPU. The annotations say where this changes the method.

The method is also the subject of two posts from Cartesia, From Tokens to Bytes I and II. They compare the scaling of H-Nets with tokenized and byte-level models. The comparisons are not part of this implementation. The authors' code is at goombalab/hnet.
